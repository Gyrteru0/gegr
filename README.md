# Расшифровщик демок Dota 2 для людей и ИИ

Программа берёт **любую** демку Dota 2 (`.dem`, `.dem.bz2`, `.dem.gz`, `.dem.zst` — Source 2,
контейнер `PBDEMS2`) и раскладывает матч по файлам, которые нейросеть может
«просмотреть как живой зритель»: покадровый таймлайн мира, полный боевой лог,
все события, чат, приказы игроков и картинки миникарты с текстовыми описаниями.

> Демки Dota 2 не зашифрованы: это protobuf-сообщения, сжатые Snappy, а внутри —
> дельты сущностей игрового мира. Сложность не в «шифре», а в объёме и бинарном
> формате сущностей Source 2. Поэтому внутри два слоя:
> **Go-движок** на библиотеке [manta](https://github.com/dotabuff/manta) (MIT)
> декодирует сущности/лог/ивенты, а **Python-обёртка** (только стандартная
> библиотека) собирает из этого удобные для ИИ файлы и рендерит миникарту.

## Быстрый старт

```bash
# 1) один раз собрать движок сущностей (нужен Go >= 1.22, https://go.dev/dl/)
python backend/setup_backend.py

# 2) разобрать демку
python decode.py match.dem
# -> рядом появится папка match_decoded/ ; начните с AI_CONTEXT.md

# несколько файлов сразу, в том числе сжатые скачанные реплеи:
python decode.py 8552595443.dem 8123456789.dem.bz2 -o razbor

# 3) глубокая аналитика поверх разбора (драки, смерти, билды, карты) и поиск моментов:
python analyze.py match_decoded/
python find.py match_decoded/ deaths --hero sven
python moment.py match_decoded/ --time 23:40 --player 4   # любой найденный момент — стоп-кадром
```

> Свежие реплеи Valve отдаёт как `*.dem.bz2`, внутри которых на самом деле
> **zstd** — программа определяет сжатие по содержимому, а не по расширению.
> Для zstd нужен один модуль: `pip install zstandard` (bzip2/gzip — из коробки).

В этой папке движок уже собран для Linux x86_64 (`backend/dota2-backend`),
поэтому на этой машине шаг 1 можно пропустить. Для Windows запустите тот же
`python backend/setup_backend.py` — соберётся `dota2-backend.exe`.

Для ИИ есть короткий рецепт: **отдайте нейросети файл `AI_CONTEXT.md`** целиком —
там составы, игра по минутам с позициями героев и ключевыми событиями и финал.
Если ИИ умеет смотреть картинки — добавьте кадры из `frames/` (их текстовые
описания уже лежат в `frames.jsonl` и в `AI_CONTEXT.md`). Для глубокого анализа —
`timeline.jsonl` и `combatlog.jsonl`.

## Что получается на выходе (`<имя>_decoded/`)

| Файл | Что внутри |
|---|---|
| `AI_CONTEXT.md` | Вся игра одним файлом: составы, хроника по минутам, позиции, смерти, предметы, финал. Главный файл для нейросети. |
| `report.md` | То же, но для человека: таблица игроков, ключевые события, чат. |
| `summary.json` | Матч в цифрах: match_id, режим, победитель, длительность, игроки, пики/баны (если демка завершена). |
| `players.json` | Игроки: ник, SteamID, герой, команда, финальные KDA/нетворс/ластхиты/предметы. |
| `timeline.jsonl` | **Каждую секунду игры**: все герои (позиция x/y и регион карты, HP/мана %, уровень, XP, живой/мёртвый и время до респауна, предметы и заряды, способности с уровнями и кулдаунами, KDA/нетворс/ластхиты), здания и их HP, Рошан, курьеры, варды, счёт, состояние игры. Плюс поле `creeps` — компактная сводка волн крипов линии по командам: сколько крипов, где центр волны, средний %HP. |
| `events.jsonl` | Лента событий: смерти героев (убийца из боевого лога), первая кровь, байбеки, мульти-киллы, покупки и тайминги предметов, левел-апы 6/12/18/25, падения башен/казарм/трона, Рошан, варды, руны, чат. У каждого события есть `source` (combatlog/snapshot/game_event/chat). |
| `combatlog.jsonl` | Полный боевой лог: урон, хил, смерти, золото, опыт, модификаторы, способности — с разрешёнными именами (`npc_dota_hero_...`, инфликторы, атакующий/цель, HP после удара). Имена героев приведены к именам сущностей таймлайна (в самом логе legacy-имена: `nevermore` → `shadow_fiend`, `wisp` → `io` и т.п.). Обычно десятки тысяч строк. |
| `chat.jsonl` | Сообщения чата + системные события чата (глифы, сканы, покупки и т.п.). |
| `game_events.jsonl` | Все игровые события движка (`dota_*`, `player_*`, ...). |
| `unit_orders.jsonl` | Приказы игроков: куда и чем кликали (движение/атака/касты/предметы/пинг-контекст) — то, что «делали руками». |
| `modifiers.jsonl` | Сырой поток таблицы модификаторов движка: ACTIVE/REMOVED, имя модификатора (`_modifier_name`), родитель/кастер/способность индексами сущностей. |
| `pings.jsonl` | Пинги и линии, которые игроки рисовали на миникарте: кто, когда (тик), координаты, для линий — точки сегментов. |
| `frames/*.png` + `frames.jsonl` | Кадры миникарты (по умолчанию каждые 5 секунд): герои кружками по командам с номером игрока и полоской HP, здания, река и лейны. В `frames.jsonl` каждый кадр описан текстом. |
| `entity_classes.json` | Все классы сущностей, встреченные в демке, со счётчиками — карта «что вообще было в мире». |
| `manifest.json` | Служебное: мета демки, счётчики, предупреждения, было ли завершено чтение. |

## Опции

```
python decode.py match.dem \
  --sample-seconds 1     # период снимков мира (по умолчанию 1 c; для длинных матчей можно 2–5)
  --frame-seconds 5      # период кадров миникарты
  --no-frames            # без картинок (намного быстрее и легче)
  --keep-raw             # оставить сырые потоки движка в <out>/_raw (сотни МБ — для отладки)
  --build-backend        # собрать Go-движок автоматически, если его нет
  --all-entities         # снимки со ВСЕМИ сущностями, включая крипов (огромные файлы)
```

## Стоп-кадр в заданный момент (`moment.py`)

Нужно не «вся игра», а один момент — где стоит герой, куда смотрит, куда
бежит и что делает прямо сейчас:

```bash
python moment.py match_decoded/ --time 05:30 --player 0
python moment.py match_decoded/ --time 12:00 --hero Razor --window 10
python moment.py match.dem --time 25:00 --hero nevermore   # сам разберёт демку
python moment.py match_decoded/ --time end                 # финал
```

На каждого выбранного героя печатает и сохраняет `moment_<время>_<герой>.md/.json/.png`:

- **позицию**: координаты + регион («мид, сторона Radiant»);
- **куда направлен**: компас по углу поворота сущности (yaw из демки) и честное
  предупреждение, если герой смотрит не туда, куда бежит (каст/атака назад);
- **скорость и направление бега** (по снимкам вокруг момента);
- **что делает**: кастует/каналит ли способность прямо сейчас (фаза каста),
  что только что применил и кого бил/от кого получил урон (боевой лог вокруг
  момента), последний приказ игрока перед моментом — движение/атака/каст/
  покупка с целью и координатами («что кликал человек»);
- HP/ману/уровень/предметы/кулдауны/KDA именно в этот момент и кто рядом;
- **активные баффы/дебаффы по именам** (например `sven_gods_strength, ещё ~30 c`):
  поток боевого лога `MODIFIER_ADD/REMOVE` проигрывается до целевого тика,
  со стеками и оставшейся длительностью;
- **цену байбека** в этот момент и время до респауна, если герой мёртв;
- **именованные объекты рядом**: `Radiant T1 мид (1365 ед., HP 1800)` — все башни
  T1–T4, казармы, трон и Рошан получают имена по геометрии карты, плюс строка
  про состояние Рошана в этот момент;
- **кадр миникарты со стрелками**: белая — куда смотрит герой, жёлтая — куда
  бежит, выбранный герой обведён белым кольцом.

> Если разбор делался старой версией, направления в нём нет — просто
> передекодируйте демку актуальным `decode.py`.

## Глубокая аналитика (`analyze.py`)

```bash
python analyze.py match_decoded/
```

Добавляет в ту же папку разбора:

| Файл | Что внутри |
|---|---|
| `teamfights.jsonl` | Драки кластерами смертей: ≥3 смертей — `teamfight`, 2 — `skirmish`. Время/место, все смерти, урон каждого участника (внёс/получил), счёт убийств, свинг нетворса за драку и итог одной строкой. |
| `deaths.jsonl` | Разбор **каждой** смерти героя: убийца (в т.ч. через саммонов — «убил Brewmaster», и Рошана), ассисты, весь урон по источникам за 10 с до смерти, позиция и регион. Срабатывание аегиса (`will_reincarnate`) смертью не считается. |
| `builds.json` | По каждому игроку: порядок прокачки способностей и талантов, порядок предметов с таймингами, счётчики использований предметов. |
| `laning.json` | Лейнинг 0–10 мин: линия каждого, оппоненты по линии, CS/денаи/золото/опыт к 10-й минуте и разница с оппонентом. |
| `economy.json` + `economy_diff.png` | Нетворс/опыт команд по минутам, разница, самый большой перелом за минуту; график разницы нетворса. |
| `apm.json` | Приказы игроков: всего, в минуту, разбивка по типам (движение/атака/касты/предметы...). |
| `heatmap_radiant.png`, `heatmap_dire.png` | Тепловые карты позиций команд за матч. |
| `deaths_map.png`, `wards_map.png`, `wards.json` | Карта всех смертей героев; карта и список поставленных вардов. |
| `analyze.md` | Всё выше человеческим текстом одной страницей. |

## Поиск моментов (`find.py`)

Каждая строка результата — момент `MM:SS`, который сразу открывается через
`moment.py --time MM:SS --player N`:

```bash
python find.py match_decoded/ deaths [--hero ИМЯ] [--player N]  # все смерти / конкретного героя
python find.py match_decoded/ item black_king_bar               # кто и когда получил предмет
python find.py match_decoded/ ability primal_roar               # касты способности/предмета
python find.py match_decoded/ towers                            # падения башен/казарм/трона по именам
python find.py match_decoded/ Roshan                             # убийства Рошана: кто и чья команда
python find.py match_decoded/ buybacks                          # все байбеки
python find.py match_decoded/ wards                             # поставленные варды (нужен analyze.py)
python find.py match_decoded/ chat [подстрока]                  # сообщения чата
python find.py match_decoded/ lowhp [--hp 10] [--player N]      # просадки HP ниже порога
python find.py match_decoded/ fights                            # драки из analyze.py одной лентой
python find.py match_decoded/ ping                              # пинги и линии по карте с регионами
```

## Дуэль 1v1 и серия игр (`duel.py`, `compare.py`)

Для практики против бота (например, Shadow Fiend против Shadow Fiend соло мид):

```bash
python duel.py match_decoded/                 # пара «человек vs самый активный враг» сама
python duel.py match_decoded/ --players 0,1   # или явно
python compare.py game1_decoded game2_decoded game3_decoded --out series/
```

`duel.py` пишет `DUEL.md` + `duel.json`: поминутная таблица двух игроков
(CS/денаи/нетворс/опыт/уровни/души), точность рейзов каждого (касты — по
кулдаунам снимков, попадания по герою атрибутируются, когда второй игрок в
этот момент тот же рейз не бросал), урон по источникам, все смерти с
респаунами, эпизоды отступлений на низком HP (просел <35% и ушёл к базе —
видно привычки бота), положение волны крипов по минутам и урон по T1.
Души Necromastery в зеркальном матчапе — оценка по ластхитам с капом из
реальных стаков боевого лога (смерть делит пополам).

`compare.py` сводит серию игр в `COMPARE.md`: CS@10, разница нетворса@10,
точность рейзов обоих, смерти, отступления и динамика первая → последняя
игра. Именно по серии видны регулярные слабости бота.

> Воркфлоу для разбора с ИИ: после игры — `decode.py`, `duel.py`, и отдать
> нейросети `DUEL.md` (+ стоп-кадры смертей через `moment.py`). Раз в
> несколько игр — `compare.py` по всем папкам и `COMPARE.md` для профиля бота.

## Как это работает внутри

1. **Внешний контейнер** читает сам `decode.py` на чистом Python (включая
   распаковку Snappy без зависимостей): магия `PBDEMS2`, заголовок
   `CDemoFileHeader`, `CDemoFileInfo` с итогами матча, перепись пакетов.
   Это работает даже без Go-движка — тогда получится честный `summary.json`.
2. **Движок** (`backend/main.go`, manta с патчами) проходит всю демку
   и стримит JSONL: боевой лог HLTV (`CombatLogDataHLTV`), чат, все игровые
   события, приказы, модификаторы (с именами из таблицы `ModifierNames`),
   пинги/линии по карте и снимки мира. Патчи правят: локальные/
   SourceTV-демки без `/dota_vNNNN/` в пути больше не падают; события можно
   слушать по маске `*`; у событий есть полный дамп полей. Вносятся
   автоматически `backend/setup_backend.py`.
3. **Сборка** (`decode.py`) двумя потоковыми проходами (память не зависит от
   длины матча): разрешает ID игроков (слот ↔ сущность ↔ SteamID), считает
   игровое время от горна (якорь — переход боевого лога `GAME_STATE` в «игра идёт»), строит таймлайн,
   выводит события из лога и из диффов снимков (работает даже там, где лога
   нет), рендерит PNG миникарты собственным кодером и пишет отчёты.

### Проверка качества
На реальном матчмейкинг-матче (8552595443, 41 минута, Dire победили) смерти
героев из `events.jsonl` сходятся с боевым логом 1-в-1 (93 смерти),
а KDA/нетворсы в `players.json` — с финальным состоянием мира и FileInfo.
На профессиональном матче 9054267340 (53 мин, Dire 49–32) анализатор нашёл
ровно 82 смерти героев — как в OpenDota с учётом смертей от нейтралов;
суммы финальных нетворсов по `economy.json` совпали с `players.json` до золота;
все 22 башни и 12 казарм получили верные имена T1–T4 по линиям.

## Ограничения и честности

- Демка, оборванная до конца матча (как локальные/SourceTV-записи), не содержит
  финального `CDemoFileInfo` — программа прямо пишет об этом, а итог
  восстанавливает из последнего снимка мира.
- В локальных демках часть сущностей может «моргать» из-за зоны видимости
  записи (PVS) — ложные «смерти зданий» отсекаются подтверждением следующими
  снимками.
- Имена предметов/способностей выводятся из классов сущностей
  (`item_black_king_bar`, `nevermore_shadowraze1`) — это канонические
  внутриигровые имена, версионно-устойчивые и понятные ИИ.
- Регион карты («мид, сторона Radiant», «топ-лейн»...) — геометрическая
  оценка по координатам, а не данные движка.
- В зеркальных матчапах (два одинаковых героя) боевой лог различает героев
  только по имени `npc_dota_hero_*` — действия, урон и модификаторы из лога
  могут приписываться обоим; приказы, позиция и фаза каста при этом индивидуальны.
- В баффах `moment.py` видны только модификаторы, которые пишет боевой лог
  (видимые): скрытые пассивки предметов туда не попадают.
- «Командная драка» в `analyze.py` — кластер смертей героев с паузой ≤45 c;
  2 смерти помечаются как стычка (`skirmish`), ≥3 — как командная драка.
- Очень старые (Source 1) и битые демки не поддерживаются — программа скажет,
  что магия/структура не та.

## Состав проекта

```
dota2_demo_decoder/
  decode.py               — главная программа разбора (Python 3, без зависимостей)
  moment.py               — стоп-кадр момента: позиция/взгляд/действие/баффы героя + кадр со стрелками
  analyze.py              — драки, разбор смертей, билды, лейнинг, экономика, APM, тепловые карты
  find.py                 — поиск моментов по времени и событиям (смерти/предметы/касты/башни/Рошан/пинги...)
  duel.py                 — дуэль 1v1: поминутная таблица пары, рейзы, души, отступления, волны крипов
  compare.py              — сводка по серии дуэлей: привычки бота и прогресс игрока
  backend/
    main.go               — движок-стример сущностей/логa/ивенты на manta
    setup_backend.py      — сборка движка (+ патчи manta) одной командой
    dota2-backend         — собранный бинарь (Linux x86_64, в этой поставке)
    manta_patched/        — пропатченная копия manta (генерится setup-скриптом)
  example/                — готовый разбор демки из репозитория-примера
```
